# 화면 제작 절차

이 저장소는 두 가지 작업만 다뤄요.

- **A. 기획 변경에 따른 as-is 수정** — 기존 화면을 고치거나 기능을 추가
- **B. 새로운 화면** — 화면이 없는 신규 기능

기획서 정리나 와이어프레임 단계는 다루지 않아요. 무엇을 그릴지는 요청자가 기획서나 요구사항으로 알려줘요.

## 공통 — 조립 순서

1. **디자인 시스템에서 시작** — 상단바·하단탭·탭·칩·버튼·폼·모달 등 화면 골격과 요소 ([03-components-ds](03-components-ds.md))
2. **빌더에서 썸네일** — 상품 썸네일·상품 정보·상품 카드·썸네일 배지·매장 썸네일 ([04 모바일](04-components-mobile.md) / [05 PC](05-components-pc.md))
3. **필요할 때만 빌더 골격 블록** — `B-Top_screen`, `B-Navigation`, `B-Content_Title` 등. 디자인 시스템에 마땅한 게 없거나 조합이 더 빠를 때. 해제해도 돼요
4. **셋 다 없으면 커스텀** — 이름 앞에 `❤︎`를 붙이고 팀에 공유

공통 규칙
- 모바일은 **iOS 375만**, PC는 **1440 기준** (1200·2000은 요청이 있거나 레이아웃이 달라지는 화면만) — [01-screen-standards](01-screen-standards.md)
- 색·텍스트·그림자는 **스타일 연결** — [02-foundations](02-foundations.md)
- 컴포넌트는 신상마켓 라이브러리 4개에서만. 검색 시 `includeLibraryKeys`로 범위 지정
- 디자인 시스템 컴포넌트는 해제하지 않고 속성(variant)만 바꿈
- 기획에 없는 정책은 지어내지 않고 질문으로 남김

## A. 기획 변경에 따른 as-is 수정

1. **받을 것**: as-is 화면 Figma 링크(프레임 단위) + 변경 내용(기획서 링크 또는 변경 요약) + 그릴 파일. as-is가 없으면 먼저 요청한다.
2. **as-is 읽기**: 화면 구조와 쓰인 컴포넌트·스타일을 파악한다 (`get_metadata`, `get_screenshot`, 필요하면 [08-audit](08-audit.md) 스크립트의 `components` 목록).
3. **변경표 확인받기**: 그리기 전에 아래 표를 보여주고 확인받는다.

   | 영역 | 구분 | 내용 | 쓸 컴포넌트 |
   |---|---|---|---|
   | 상단 | 유지 | — | — |
   | 상품 리스트 | 변경 | 2열 → 3열 | `Info/Text` Size=Small 3열 |
   | 리스트 위 | 추가 | 필터 칩 | `chipFilledSmall01` |
   | 하단 배너 | 삭제 | — | — |

   기획서에 등급별·조건부 분기 표가 있으면 분기마다 행을 나눠 빠짐없이 넣는다.
4. **바뀌는 부분만 수정**: as-is를 복제해 그 위에서 고친다. 바뀌지 않는 영역은 건드리지 않고, 새 요소는 as-is와 같은 컴포넌트 계열로 맞춘다.
5. **상태 확인**: 변경 때문에 새로 생기는 상태를 [07-states-checklist](07-states-checklist.md)로 확인한다.
6. **검수**: [08-audit](08-audit.md)을 실행해 고친다.
7. **보고**: 변경표와 대조해 한 것과 남은 것을 나눠 보고한다. 일부만 했으면 "완료"라고 하지 않는다.

## B. 새로운 화면

1. **받을 것**: 기획서 링크 또는 요구사항 + 그릴 파일. 비슷한 기존 화면이 있으면 참고 링크.
2. **화면 목록 확인받기**: 그리기 전에 그릴 화면을 보여주고 확인받는다.

   | 화면 | 플랫폼 | 필요한 상태 | 참고 |
   |---|---|---|---|
   | 목록 | iOS 375 | 기본 / 빈 화면 / 로딩 | 06 템플릿 "섹션+리스트" |
   | 상세 | iOS 375 | 기본 / 품절 | 기존 상세 화면 |

3. **배치 정하기**: [06-templates](06-templates.md)에서 가장 가까운 유형의 배치·여백을 참고한다.
4. **조립**: 위 "조립 순서"대로. 프레임 이름은 `[iOS] 화면명`, `[PC 1440] 화면명`.
5. **상태 확인**: [07-states-checklist](07-states-checklist.md).
6. **검수**: [08-audit](08-audit.md).
7. **보고**: 화면 목록과 대조해 그린 것과 남은 것을 나눠 보고한다.

## Figma 작업 팁 (그동안 겪은 오류)

- 컴포넌트를 처음 쓸 때는 바로 넣지 말고 variant 이름과 속성을 먼저 확인한다. 버튼처럼 글자 속성이 없어서 안쪽 텍스트 레이어를 직접 바꿔야 하는 경우가 많다.
- 글자를 바꾸기 전에 해당 폰트를 먼저 불러온다.
- 텍스트는 "자동 높이"를 먼저 설정하고 글자를 넣는다. 그 뒤에 크기를 다시 고정하면 줄바꿈이 깨진다.
- 한 번 실행할 때 페이지 전환은 한 번만 한다. 여러 페이지 작업은 나눠서 실행한다.
- 새 요소는 화면 프레임 안에 바로 만든다. 밖에 만들고 옮기면 엉뚱한 위치에 남는다.
- 오토레이아웃 안 요소는 좌표로 옮겨지지 않는다. 간격 값으로 조정한다.
- 섹션을 만들 때마다 스크린샷으로 잘림·겹침을 확인한다.
- 라이브러리 원본 파일에는 그리지 않는다.
